# r18 补回侧面覆盖：wrap-wide

## 用户选择与本轮变量

用户选择 r17 wrap 方向继续完善，原偏黑亮银保留。r17成为美术对照基线，
不是全部画质与实际呈现帧率通过。本轮仅延长现有fill的后段，尝试改善
正侧下门板相对r16偏暗的取舍；不进入世界空间反射节点。

r18：fill宽7.4，高1，位置[5.65,3.05,1.1]，目标[1,0,1.1]，辐射/强度7.68。
相对r17宽5.6、中心z=2，z正向边缘保持4.8，另一边由-0.8延至-2.6。
发光面积与面积×辐射增加32.14%，不是同能量对照。其余三灯、墙地、相机、
曝光和车漆保持。灯数、运行反射预算、环境尺寸和绘制时钟不增加。

显式入口carStudioFinish=wrap-wide；原wrap和普通入口保持。按同一配置
构造真实灯板、面积灯和离线反射源，不将车身高光烘死在颜色贴图上。

## 后台短测

两次顺序运行，1440×1000、各自绕行/开门/分离30秒；无重载长测。
performance与performance-wrap-control报告均passed=true，无错误/失败请求，
仅同源访问。单次加载不是冷缓存分布，不作因果提速结论。

| ---------------------------- | ---------------- | ---------------- |

| 增强就绪                     | 60.468秒         | 58.954秒         |
| 绕行JS提交间隔中位/P95       | 24.8 / 32.8 ms   | 23.6 / 31.1 ms   |
| 开门JS提交间隔中位/P95       | 26.5 / 35.3 ms   | 31.1 / 39.8 ms   |

| 匿名compute组GPU查询中位/P95 | 7.471 / 9.568 ms | 7.340 / 8.847 ms |

r18开门与分离的提交间隔更长，绕行略短；没有证据把差异归因于纹理大小或
灯数，也不能用compute组耗时下降否认提交间隔退步。单次顺序测试不能排除
运行环境波动，性能中立尚未证明。以上均不是屏幕实际呈现间隔或整帧GPU时间，
30FPS目标仍待验证。本轮保留独立候选，不能宣称“无性能影响”或切换默认。

本轮达到工程接入及画面对照交付；整体画质、实际呈现与性能取舍仍未验收。
下一步应先核对动态帧开销和既有细边白点，避免继续扩大灯光或增加实时算法。
