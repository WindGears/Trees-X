# heritage-museum 前端复用评估

日期：2026-09-17。参考项目：`I:/ssr/NIXUS/heritage-museum/heritage-web`。

实施状态：早期的编辑式长页方案已被桌面工作台方案取代。保留的参考只有全屏主舞台、极端字号差和细线层级；浅色入口网格、Interaction Story 与长页面节奏已移除。gesture bridge 仍由 ProductShowcase 提供，TresCanvas 仍只有一个。

## 结论

可以利用，而且能解决 Trees X 当前最明显的问题：三维功能已经完整，但页面仍像“左侧说明 + 右侧查看器”的技术演示。参考项目真正值得迁移的是编辑型信息层级、全屏首屏、深浅场景切换、模块化滚动节奏和统一动效规则。现有 TresJS 场景、HDR、扫描层、商品交互和手势底座应继续保留。

不应直接复制参考项目的页面组件。当前 `HomeView.vue` 约 725 行、`SiteHeader.vue` 约 350 行，不符合本项目 Vue 文件不超过 300 行的约束；它还依赖 Vue Router、Element Plus、接口数据、图片内容和独立的 WebGL 液体模拟。

## 当前差距

| Trees X 现状                     | 参考项目提供的解法                              | 改造方向                                                 |
| -------------------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| 首屏是左右两栏，模型只占右侧局部 | 近一屏高的集中式 Hero，标题与媒体共同成为主视觉 | Canvas 扩展为全宽/全屏舞台，标题和产品身份叠放在安全区   |
| 控件和体验选项像开发面板         | 操作被组织为清楚的入口、章节和场景              | 将视角、配色、部件、结构收为底部观察 Dock 与四个探索入口 |
| 全页持续近黑，缺少章节变化       | 深色 Hero、浅色入口、深色内容、浅色观点交替     | 使用石墨黑、雾银白两种场景，不复制博物馆的棕红色         |
| 能量环、粒子与正文关系较弱       | 视觉背景、标题、入口和滚动节奏共同表达主题      | 让三维舞台只主导 Hero，后续章节围绕真实交互能力叙事      |
| 详情区是普通定义列表             | 大标题、细线、编号、留白构成编辑式节奏          | 把详情改造成三至四个大章节，保留真实产品事实             |

## 可复用部分

### 1. 视觉结构

- `HomeView.vue` 的全屏 Hero、超大双行标题、角落索引和垂直滚动提示可直接转译为产品发布页结构。
- `door-grid` 可转成四个真实探索入口：360° 观察、外壳配色、部件聚焦、外观结构。入口只调用已有 Pinia 意图，不增加假功能。
- `archive-bento` 的 12 列节奏可以用于后续多商品空间；当前只有一个 GLB 时不应显示虚构商品卡。
- `quote-chamber` 可转成产品设计主张与技术说明，用雾银浅底打破整页黑色。
- `process-stack` 可转成“观察—聚焦—拆解—手势”的交互流程说明。
- `SectionHeading.vue` 的标题/说明双列结构适合抽成不超过 100 行的 `EditorialHeading.vue`。

### 2. 动效工程

- `motion/tokens.ts` 的时长、缓动和强度分级思想可合并进当前 `.ai/animation-rules.md` 与 `useAnimation.ts`，避免每个区块单独发明参数。
- `useMotion.ts` 使用有作用域的 `gsap.context`、重建和清理，和当前工程规则一致，可以借鉴实现方式，但不直接复制依赖关系。
- 首页的标题分行揭示、章节细线绘制和滚动进入动画可以复用；动画只作用于 `transform`、`opacity` 和 `clip-path`。
- `useMotionBudget.ts` 的分级思想可与现有 `useVisualPerformance.ts` 汇合，让 DOM 动效和 Three 画质共享 `full/reduced/off` 判定。

### 3. 响应式方法

- Hero 从居中大标题自然收缩为移动端 38–64px，入口从四列变两列，后续变单列，这套断点逻辑可复用。
- 参考项目通过真实内容重排保持移动端密度；Trees X 应保留完整键盘/触控控制，不能在小屏仅隐藏功能。

## 不复用部分

- `ImmersiveStage.vue` 和 `LiquidVanilla`：会建立第二个 WebGL Canvas，并持续运行流体模拟，与 TresJS、Bloom 和手势推理争用 GPU。
- `LightCursor.vue`：会隐藏系统指针，与当前模型热点和手势指针形成两套光标语义。
- `InkRouteTransition.vue`：目前 Trees X 是单页单商品，没有值得覆盖全屏的路由切换；多商品路由确定后再评估。
- 博物馆照片、棕红/宣纸色、颗粒纹理和非遗文案：不属于商品系统，也没有在本项目中确认资源许可与品牌适配。
- Element Plus 和参考项目的接口、认证、场景 Store：前台不引入，后台阶段再单独评估。

## 建议的新页面骨架

1. **Product Stage / 100dvh**：唯一 TresCanvas 占满首屏；产品位于中央偏右，标题置于左下安全区。保留 HDR、粒子、扫描演出和现有输入中止规则。
2. **Explore Modes / 雾银浅场景**：四个入口对应已有功能。悬停只改变排版与缩略预览，点击后滚回舞台并执行真实状态。
3. **Designed in Layers / 深色粘性章节**：固定一个模型展示区，右侧依次说明轮廓、驱动单元、顶部旋钮和结构模式。滚动镜头必须在用户手动交互后让出控制权。
4. **Interaction Method / 浅场景**：用三步大字号流程解释鼠标、触控和手势；把摄像头入口放在这里，首屏不承担诊断 UI。
5. **Technical Notes / 深色收尾**：列出本地处理、画质降级、模型格式和资源许可，不编造商品参数。

## 实施顺序

### A. 先重构页面骨架

- 新建 `ProductHero.vue`、`ExploreModes.vue`、`InteractionStory.vue`、`EditorialHeading.vue`。
- `App.vue` 继续只装配；`ProductViewer.vue` 继续是唯一 Canvas 所有者。
- 将现有商品体验操作通过 props/emits 或 Pinia 意图接入新入口，不改 Three 生命周期。
- 首轮只改布局、排版和状态位置，先确保所有现有测试继续通过。

### B. 再建立滚动叙事

- 使用现有 Lenis + GSAP 时钟增加局部 ScrollTrigger。
- 章节进入只驱动已有相机预设和结构进度；拖动、按钮和手势立即中止。
- 减弱动态直接显示章节最终状态，不创建 scrub 时间线。

### C. 最后扩展多商品空间

- 只有在第二个真实 GLB 和商品配置到位后，才把入口网格升级为 Product Universe。
- 路由、共享元素转场和商品预加载在这一阶段引入。

## 验收重点

- 1440×1000 首屏模型视觉占比达到约 45%–60%，标题不与产品轮廓、热点和顶部画质入口重叠。
- 390px 与 320px 保留视角、缩放、配色、部件、结构和手势入口，无横向溢出。
- 全页仍只有一个 TresCanvas；浅色章节离开舞台后不会让 Three 持续渲染。
- 重构后继续通过 `npm run check`、`npm run build`、视觉、体验和手势脚本。
- 最多进行一轮桌面/移动端集中截图修正。
