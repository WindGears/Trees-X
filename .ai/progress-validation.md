# B2：双案例可逆结构探索验收

2026-10-08。本轮按用户批准方案，在现有工作台上实现音箱分层与汽车双门的统一进度控制。使用程序化样板，真实GLB只作为兼容工程夹具；不算正式资产/材质验收，不包含管理端、手势或新特效。当前开题新增段落仍区分拟研究目标与原型验证，未改写用户的DOCX。

## 如何演示

启动后端8089与前端5181，进入音箱 → 结构与动作 → 展开 → 暂停 → 拖进度至43.7% → 自由旋转/选择单元 → 继续或合拢 → 复原动作。进度0—100%，步长0.1%；全程2秒，部分行程按距离缩短。分层时可独立转动旋钮，动作复原不改变旋钮或外观。

切换汽车 → 结构与动作 → 打开 → 任意进度观察 → 展开部件，核对双门旋转与分离位移共同生效。复原动作只关门、保留分离；还原商品恢复默认配色、动作、结构与镜头。复位视角只改变镜头并暂停进度。

旋转、缩放、命名视角与部件选择暂停进度，保留当时姿态；继续必须主动触发。关闭面板保留状态/播放；切换商品取消旧播放并初始化新商品。页面隐藏暂停，返回不自续；上下文恢复保持当前进度并暂停。减弱动态自动操作直接到目标，滑条与键盘定位仍可用。

## 实现与边界

- ProductPresentation v3兼容v1/v2，资源、舞台与API路径不变。motion轨道按node/range/translate-offset或rotate-axis-angle组织；轴使用单位向量，单段旋转≤π。所有参数有限，引用/ID/区间/通道冲突前后端校验。
- motionPose绑定初始局部位置/四元数，保留原父子层级，每次由进度计算；不累计增量。motionPlayback的GSAP只补间数字，按剩余距离计算时长。旧行为按实际注册能力启用，不覆盖新轨道的变换通道。
- 音箱前面板、单元、外壳、旋钮分阶段移动；原结构意图通过structureActionId映射至同一个progress动作，旋钮旋转独立。汽车双门旋转与既有分离位移独立组合。打字机保持旧联动和结构。
- Three对象/补间只在适配器/控制器；实时反馈和恢复检查点在WorkbenchRoot局部motionSession，按商品/选择代次过滤。Pinia只保存操作意图。播放反馈限15Hz，手动定位与暂停/完成即时同步。
- 热点anchor可选局部Vec3，使用当前节点世界变换计算投影及聚焦；旧配置仍取节点原点。受控GLB复用原几何，唯一资源释放方不变。
- V5追加迁移仅升级匹配原默认配置的音箱/汽车；保留基础信息、封面和自定义配置，跳过原因记录INFO。V1—V4原文件未改。业务库当前两件为v3，打字机为v1。
