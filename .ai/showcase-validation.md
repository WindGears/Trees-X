# WebGPU 答辩候选验收

## 运行入口

本机准备时在 PowerShell 设置 `$env:TREES_DEMO_SHOWCASE = '1'`。使用 `npm run demo:prepare` 核对两份运行包、R18 烘焙、石材和 KTX2 解码器，再用 `npm run demo:start` 启动。本机汽车 4K 派生包及其登记从已有资产按制作说明准备。运行入口为 `/?renderPipeline=showcase&product=reventon`，管理预览入口为 `/admin?renderPipeline=showcase`，显式兼容入口为 `/?renderPipeline=webgl`。

展品通过同一工作台 WebGPU 宿主切换。汽车的首帧使用 R18 环境和完整车漆、玻璃、地面倒影。取得首帧后读入 DDGI 辅助图，空闲时接入实时反射、自阴影和间接光。打字机先绘制 WindGear v2 的原生材质，再接入原实时材质支路。钢琴使用 PBR 光栅，纯相机操作复用方向光阴影。两件展品的房间复用 R18 石材与墙地结构，并分别调整布光。FSR 留待演示版本验收之后评估。

## 本机测量

隔离的 `trees_x_showcase_test` 通过真实 Spring Boot API 导入三件正式配置。Edge 无头运行在本机 NVIDIA GPU，实际绘制 1440×1000。每件用三个全新的浏览器上下文冷加载，浏览器 HTTP 缓存关闭。操作统计来自约七秒的连续绕行，GPU 统计为分通道 timestamp-query，原始分组见验收报告。三个 Chromium 跟踪均缺少足量且可归属到页面的实际呈现时间戳，实际呈现预算待验收。

| 展品   | 完整材质可操作，三次      | 中位 / 目标    | 绕行 JS 提交间隔中位 / P95 |
| ------ | ------------------------- | -------------- | -------------------------- |
| 打字机 | 8.118、8.312、7.816 秒    | 8.118 / 3 秒   | 25.0 / 33.1 ms             |
| 钢琴   | 2.709、3.357、2.611 秒    | 2.709 / 5 秒   | 44.1 / 67.5 ms             |
| 汽车   | 20.984、18.574、17.783 秒 | 18.574 / 12 秒 | 23.5 / 32.0 ms             |

R18 第一组完整增强在导航后 56.049 秒就绪。此前整场预编译的首轮 R18 在 36.991 秒开放操作。当前首帧与完整增强分开统计。钢琴实际绘制探针观察到纯相机绕行零次阴影通道提交，剖切姿态一次。打字机分层、钢琴八段、汽车开门与分离、三件部件聚焦以及钢琴到打字机的同宿主切换通过。全部浏览器请求同源。启动记录、WebGPU 画面、时间戳跟踪位于 `artifacts/showcase/validation/`。

打字机与汽车的加载仍超目标，钢琴提交间隔偏长，实际呈现待测。`showcase` 保持显式候选，普通入口的晋级以联合画质、操作和性能验收为准。

## 管理、恢复与离线包

- 钢琴管理预览的取景回填、保存、前台读回与测试数据恢复通过。证据在 `artifacts/showcase/admin-save/report.json`。
- R18 管理预览使用实际 WebGPU、双射线 SSR、自阴影和 DDGI。销毁真实 GPU 设备后恢复镜头、暂停姿态和光照，管理预览退出后数据库内容摘要一致。证据在 `artifacts/showcase/admin-reventon/report.json`。
- `demo:prepare` 和 `demo:doctor` 已核对本机运行文件与生产构建。隔离库通过正式 JAR 和本地预览启停。只允许本机请求的浏览器检查验证了汽车、钢琴、打字机依次切换，旧汽车释放，Canvas 和 renderer 一直相同。WebGPU 适配器不可用时，实机进入可操作的 WebGL2 兼容模式。证据在 `artifacts/showcase/package-handoff.json`。

## 五分钟演示顺序

1. 开场前打开汽车答辩入口，等待亮银摄影棚和增强状态稳定。
2. 先转动车身，展示灯板高光和地面倒影，再打开双门，聚焦座舱并展示部件分离与复原。
3. 从目录切换打字机，演示按键联动、分层暂停、部件标签和回退。
4. 切换钢琴，依次打开剖切、弦列和全部平铺取景，展示形变与结构说明。
5. 在管理预览采集取景，展示配置如何回填。论文可用三种结构演示说明渲染宿主和交互规则的复用，反射、自阴影及加载调度分别引用实测记录。
