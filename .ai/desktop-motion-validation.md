# 桌面动效与操作验收

生产预览在本机 5183，正式展品使用 8089 的真实目录与详情。浏览器从后台启动。管理演练使用 8091 的独立 MySQL 恢复库。

## 访客走查

- 从总览切换打字机整机和分层图，再使用主按钮进入工作台。分别暂停工作台代码和商品详情请求，核对两个阶段的封面、标题、匀速指示及就绪前禁用状态。总览阶段没有 Canvas 或模型请求。
- 在打字机分层中暂停、继续、聚焦部件并返回全景。检查右侧面板开合、结构／外观／部件切栏、键盘输入、两次 Escape 的关闭顺序与焦点恢复。
- 让钢琴详情请求迟到，再切回打字机。核对实际场景模型身份和原 Canvas／renderer。继续观察钢琴击弦机构、汽车开门与座舱、同时开门与分离。核对浏览器前进／后退及汽车详情失败后的就地重试。
- 检查 1280×720、1440×1000、1920×1080 的总览与工作台构图。三件展品的原尺寸 WebGPU 输出均记录为 1440×1000。另验证减弱动态和 WebGL 兼容模式，加载指示静态显示，分层直接到达目标。

走查修正了三处问题。提前加载界面样式造成浅色旧主题覆盖暗色展厅，影响错误提示与引线可读性。工作台代码加载与三维加载使用不同顶栏高度。历史回退时旧展品的结构按钮短暂残留。修正后完整桌面浏览器回归通过。

## 管理走查

用打字机配置完成登录、修改介绍、未保存预览、右键平移、回填默认取景、手动保存和前台重载。确认预览前后只有一个活动 Canvas，回填前数据库保持原内容，保存后实际访客镜头复现，再验证部件聚焦和结构动作。隔离商品在退出时恢复。

编辑页在三个桌面尺寸都通过横向布局检查。完整预览截图、编辑页截图和 JSON 报告位于 `artifacts/desktop-motion/admin-acceptance/`。独立恢复库就绪后，使用 `CHECK_URL=http://127.0.0.1:5183`、`DEMO_ADMIN_SHOWCASE=1`、`DEMO_ADMIN_PRODUCT=typewriter-study` 和 `DEMO_ADMIN_DESKTOP=1` 运行 `node scripts/demo-admin-flow-check.mjs`。

## 工程检查

- `npm run build`、架构检查、模型校验、1018 项 Vitest 测试和独立工具测试通过。
- `npm run check` 的类型与 ESLint 阶段通过，全仓格式步骤被本轮前已有的 `PERFORMANCE_OPTIMIZATION.md` 阻断。后续检查独立执行，改动文件的格式单独校验。
- Chrome 长任务记录包含等待真实模型时的主线程停顿，本次后台录制中最长约 6.18 秒。界面过渡的验收与模型启动性能分别记录，录制结果用于定位停顿。

访客截图、录屏和 JSON 报告位于 `artifacts/desktop-motion/final/`。汽车失败页另检查封面解码完成后的状态，封面、说明与重试入口都属于当前展品。用 `CHECK_URL=http://127.0.0.1:5183` 和 `EXHIBITION_RECORD=1` 运行 `node scripts/exhibition-flow-check.mjs` 可重现录制。
