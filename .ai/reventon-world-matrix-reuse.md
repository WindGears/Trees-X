# R18 同帧世界矩阵复用

后台 CPU 采样将场景提交和浏览器回调对齐。绕行样本中有两段约 126–129 ms 的间隔，其中约 98–102 ms 在主线程空闲。开门和分离的部分长任务处于 Three 绘制栈中，采样间隔有时中断 30–80 ms，无法仅凭间隔结束后的调用栈把停顿归因于单个函数。持续可复现的开销包括场景矩阵遍历和逐帧标注测量。采样证据位于 `artifacts/r18-startup-deep/runtime-cpu-study-r18*`。

R18 使用单个同步渲染协调器。它在主画面、平面倒影和接触阴影之前更新场景世界矩阵，在这些绘制期间关闭 Three 对同一场景的自动刷新，并在 `finally` 恢复原设置。运动历史直接捕获当前场景矩阵，继续更新相机矩阵。DDGI 仍在原异步更新位置刷新其输入。矩阵复用范围仅覆盖已核验 R18 的同步多通道绘制。[Three r185 绘制实现](https://github.com/mrdoob/three.js/blob/r185/src/renderers/common/Renderer.js) · [Object3D 矩阵更新](https://threejs.org/docs/pages/Object3D.html#matrixWorldAutoUpdate)

## 实测

同一构建交替运行两次参考和两次复用，每次以 1440×1000、实际 NVIDIA WebGPU、完整 R18 材质及光照完成各 9 秒绕行、开门和分离。记录场景根 `updateMatrixWorld` 的调用次数与耗时。

| 动作 | 每帧调用次数，参考 → 复用 | 每帧调用耗时，参考 → 复用 | JS 提交 P95，参考 → 复用 |
| ---- | ------------------------- | ------------------------- | ------------------------ |
| 绕行 | 4.00 → 1.00               | 0.35–0.37 → 0.12–0.13 ms  | 15.7 → 15.9–16.1 ms      |
| 开门 | 6.17–6.20 → 1.21–1.22     | 0.51–0.52 → 0.12–0.13 ms  | 22.8–22.9 → 22.8–23.0 ms |
| 分离 | 6.20–6.21 → 1.22          | 0.51–0.54 → 0.13–0.14 ms  | 22.9–23.1 → 23.0 ms      |

矩阵更新每帧减少约 0.22–0.41 ms。端到端提交 P95 基本持平，屏幕呈现间隔待验证。全景、开门、分离和亮橙状态下，四次运行的模型世界矩阵摘要逐项相同。对应截图的全画面 8 位 RGB 平均绝对差为 0.018–0.061，参考两次之间为 0.028–0.039。实机保留单 Canvas、4K BC7、双射线反射、主软箱自阴影和 DDGI。原始报告及截图位于 `artifacts/r18-startup-deep/world-matrix-paired-*`。
