# R18 原生 BC7 贴图后台解包

后续首次绘制优化见 [R18 材质程序复用](reventon-material-program-reuse.md)。

## 定位

同一个生产构建在 1440×1000、Edge 无头及真实 NVIDIA WebGPU 下交叉比较。提前读取 8 或 16 张贴图，最多有 15 张在 GLB 结束前到达。GLB 自身传输也变慢，材质准备与完整首帧未获得稳定收益，所以保留原下载顺序。

独立 CPU 采样中，模型准备阶段有约 1.86 秒主线程采样位于 Zstandard 解包调用栈。第一次完整增强绘制有约 5.29 秒位于 Three 渲染调用栈，主要花在节点图建立。后者是 CPU 采样的累计时间，不能解释为 GPU 着色器执行时间。

## 实现

仅已核验 R18 流式资源包、匹配的 BC7 本机缓存及适用的解码档位使用新路径。继续验证原文件摘要。两个解析所有的 Worker 使用 Three r185 自带的 Zstandard 解码器。Worker 只复制各自正在处理的压缩输入，把解包后的 mip 缓冲转移回加载器。原输入未被分离，线程不可用、解码失败或纹理格式不匹配时可以使用现有 Three 路径。选品取消终止两个 Worker，原解析所有者仍统一回收纹理。

保留原 BC7 GPU 格式、4K 上限、全 mip、色彩空间、模型、动作及所有 R18 光照。没有额外 renderer、时钟或 GPU 资源。单独加 `&r18Zstd=reference` 可对照主线程解包。

## 实测

| 同构建冷启动 | 进入材质与光照准备 | 界面就绪 | 完整首帧 GPU 队列结算 |
| ------------ | ------------------ | -------- | --------------------- |
| 主线程 A     | 6.39 秒            | 15.81 秒 | 15.96 秒              |
| 两个线程 A   | 4.70 秒            | 13.78 秒 | 13.93 秒              |
| 两个线程 B   | 4.55 秒            | 13.42 秒 | 13.56 秒              |
| 主线程 B     | 5.94 秒            | 14.83 秒 | 14.98 秒              |
| 拦截 Worker  | 6.04 秒            | 14.97 秒 | 15.12 秒              |

每次均核对同一汽车资源、完整输出、R18 环境、主软箱自阴影和 DDGI。实机对照读取 74 个不同贴图的 962 个 mip，共 1,655,353,952 字节。两条正常路径及拦截后回退的各层尺寸和 SHA-256 全部一致。80 个模型 GPU 纹理分配按实际格式估算均为 1,789,571,840 字节。

原始对照在 `artifacts/r18-startup-deep/native-bc7-release-*.json`。预取试验及独立 CPU 采样分别在同目录 `prefetch-study-*.json` 与 `startup-cpu-reference.cpuprofile`。测试均在后台运行。首帧结算使用 WebGPU 队列栅栏；显示器实际呈现间隔未由本次测试认证。

## 工程回归

拦截两个正在解包的 Worker，切到打字机后均退出，返回汽车在同一 Canvas 和 renderer 上完成 74 个解包任务。三件展品联合回归、汽车管理取景和真实设备恢复通过。证据见同目录 `native-bc7-cancel.json`、`native-bc7-showcase/report.json` 与 `native-bc7-admin/report.json`。

生产构建、类型、Lint、架构、模型检查、1013 项单测及相关工具测试通过。全库 `npm run check` 在已有的 `PERFORMANCE_OPTIMIZATION.md` 格式处停止，后续检查已单独运行。
