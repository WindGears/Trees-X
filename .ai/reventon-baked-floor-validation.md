# 汽车静态反射候选：阶段一（2026-10-24）

## 范围与事实

用户同意将固定摄影棚反射离线保存，减少地板实时反射开销；不能把固定汽车倒影画在地板上。
本批为基础接入：保存 revision 10 现有 Three WebGPU 静态捕获，不宣称已经制作 Blender/Cycles 高质量光照图。
没有修改灯光、曝光、地砖材质、汽车机构、配置版本或数据库；其他商品保持。

`carShowroom=cold-studio&carFloor=baked` 在已核验 WebGPU studio 汽车中启用。
普通冷白棚保留实时捕获与地板 SSR，可作为同输入对照。

- 两份线性 HDR 共 43,864,820 字节（gzip），解压 142,606,336 字节；无损保存原 Float32，尺寸保持4096×2048／1024×512。
- 候选不创建捕获房间副本、CubeRenderTarget 和转换目标，不进行12次六面捕获绘制。PMREM仍需首次准备；不宣称加载必然更快或环境显存整体降低。
- 地板的 specular MRT 输出为0：跳过地板 SSR 射线与修正，保留原生环境、Physical粗糙度、动态接触阴影及漫反射GI。汽车的SSR、透明支路和动作保持。
- 不销毁全屏SSR目标，因为汽车仍使用；不能把局部跳过称为彻底移除SSR开销。
- 文件摘要、解压摘要、配置一致性及取消检查先于纹理发布；失败沿用可操作基础环境并报告错误。部分成功或迟到结果由舞台唯一释放。
- 不包含汽车倒影，也未解决所有中央探针空间近似。地板真正的离线间接光/建筑遮蔽lightmap与更高质量离线探针仍待制作。

## 本批验收

- 86项摄影棚、材质桥、信号及SSR分类测试通过，包括真实压缩文件读取、配置失效、损坏、取消、部分失败及唯一释放。
- `npm run build` 通过。`npm run check` 的typecheck和ESLint通过，停在既有用户文件 `PERFORMANCE_OPTIMIZATION.md` 格式问题；未修改该文件。
- 首次浏览器原版加载发生 `ERR_NO_BUFFER_SPACE`，保留失败记录。重试原版五取景和动作通过；候选发现预览服务自动解压`.gz`导致摘要校验失败，已改用保持原字节的`.bin`扩展名。实际HTTP下载摘要已核对。保留该失败，不将基础回退冒充候选成功。
- 修正后生产候选通过：1440×1000、单Canvas/同renderer、实际DDGI及主软箱阴影ready、正面/侧面/背面/开门/0.6分离、合拢复原，无GPU错误或页面错误。两次资源请求、现场捕获0次，观察和动作不触发重拍。报告 `artifacts/car-showroom/baked-floor/report.json`；原版完整对照留在 `second-attempt.json` 的baseline run，失败记录独立保留。
- 人工查看正面与侧面图：保持原来的大面积地面灯光亮斑，静态保存没有显著提升光照造型；车身仍有过硬的明暗分割、地砖缝细边锯齿，地面无汽车倒影。不能宣布达到概念图，也没有实际呈现帧率/提速成绩，默认不切换。
