# R18 首帧管线预编译

## 开销来源

在 1440×1000 的真实 NVIDIA WebGPU 启动追踪中，软箱阴影准备的队列等待于 15.791 秒发起，约 0.2 毫秒后返回。随后进入首帧阶段，创建了 99 个渲染管线及 157 个 WGSL 模块。界面在 21.34 秒进入就绪状态，该状态前提交的 GPU 工作在 31.87 秒结算。队列结算包含此前提交的工作和浏览器回调调度。[WebGPU 队列接口](https://gpuweb.github.io/gpuweb/#dom-gpuqueue-onsubmittedworkdone)

## 后台预编译

以真实 R18 首帧捕获 96 份显式绑定布局的渲染管线描述及 WGSL，压缩登记约 750 KB。运行时由当前模型选择启动同一 GPUDevice 的 `createRenderPipelineAsync`，与模型、材质和舞台的准备重叠。Three.js 在真实绘制时沿用正常管线创建流程。预编译不成为首帧等待项，成功对象保活至首帧提交，切换或销毁取消下载并释放引用。设备恢复使用新设备重新准备。缺失、摘要错误或原生编译失败时继续运行场景本身的编译路径。[WebGPU 异步管线创建](https://gpuweb.github.io/gpuweb/#dom-gpudevice-createrenderpipelineasync)

只在已登记的汽车 4K 包与 Three r185 的答辩入口使用。在可运行的 R18 上执行 `npm run asset:reventon-native-pipelines`，重新构建 `demo:prepare`。登记和压缩描述符保存在本机。用 `&r18Pso=off` 关闭预编译作同构建对照。

## 初步同设备验证

无头 Edge 使用 1440×1000 的真实车身、DDGI、软箱自阴影及 4K BC7 材质。在一次交叉试验里，原路径的 GPU 队列结算为 35.89、32.78 秒。直接复用提前编译对象的实验为 30.71、22.33 秒，首帧 99 次创建请求各命中 97 次。仅提前编译并保留 Three 原生创建的样本为 21.26 秒，采用这条接入方式。

追踪和试验报告位于 `artifacts/r18-startup-deep/shadow-fence-trace-base.json` 和 `pso-native-compiles-*.json`。时间不代表显示器实际呈现帧率。

## 构建实测

同一生产构建用 `r18Pso=off` 交叉对照。两组均核对 1440×1000、4K BC7、DDGI、软箱自阴影和唯一 Canvas。

| 顺序     | 界面就绪 | GPU 队列结算 | 就绪至结算 |
| -------- | -------- | ------------ | ---------- |
| 原路径 A | 29.02 秒 | 44.68 秒     | 15.66 秒   |
| 预编译 A | 32.51 秒 | 32.64 秒     | 0.13 秒    |
| 预编译 B | 25.43 秒 | 25.52 秒     | 0.10 秒    |
| 原路径 B | 21.27 秒 | 37.81 秒     | 16.54 秒   |

第一对测试开始时，显卡采样负载为 80% 和 72%。第二对为 16% 和 12%。整页启动仍随负载变化，预编译 A 超过了 30 秒。

带诊断的独立对照中，96 个原生异步管线请求在 0.90–3.03 秒内提交并完成。首帧阶段新增的唯一 WGSL 源码由 157 份降至 1 份，99 个原生创建请求仍照常执行。该对照的 GPU 队列结算为 39.96、25.66 秒。全景与双门打开的车身取样区，8 位 RGB 平均绝对差为 0.154、0.190。灯板采样区逐像素一致，地面取样区平均绝对差在 0.0002 以内。缓存内容损坏和 404 时均完成带原 4K 材质、DDGI 和软箱阴影的首帧。

构建交叉对照、带诊断对照、截图及故障回退原始记录分别为 `pso-packaged-*`、`pso-visual-*` 和 `pso-fault-*`。

## 联合验证

三件展品及同宿主切换通过，联合测试中的汽车在 22.18 秒结算。拦住缓存请求后切到打字机，旧请求被中止，回到汽车重新读取缓存，整个过程使用同一 Canvas 和 renderer。管理预览、取景回填和真实 GPUDevice 丢失恢复共四项通过，未写入配置。报告为 `pso-showcase/report.json`、`pso-cancel.json` 和 `pso-admin/report.json`。

生产构建、类型检查、ESLint、架构和模型检查通过。全库 `npm run check` 停在已有的 `PERFORMANCE_OPTIMIZATION.md` 格式检查。默认单测并发的一次运行出现超时，用两路复跑相关 36 项、用四路复跑全量 1009 项均通过。演示工具、实时探针、打字机资源与汽车运行工具测试通过。

5181 演示包重建后，两次新浏览器冷启动分别为 22.61／22.75 秒和 21.70／21.81 秒，依次表示界面就绪和 GPU 队列结算。均读取真实的 750,413 字节缓存，静止提交归零后拖动可重新唤醒，窗口调整后仍只有一个 Canvas。报告为 `pso-release-r18-a.json` 和 `pso-release-r18-b.json`。
