# R18 首帧与反射开销实测

## SSR 未命中

R18 的原生材质保留摄影棚环境照明。双射线 SSR 在此基础上提供有符号修正，未命中输出零色并保留距离标记 10000。Three r185 的随机 SSR 仍为零强度的未命中路径创建两份 HDR 采样纹理。[Three r185 SSR 源码](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/tsl/display/SSRNode.js)

在已核验 R18 上，以实例局部的常量零色取代这两个采样器。命中着色、两条射线的采样序列、过滤、环境光和画面分辨率沿用原参数。桥接检查版本及采样器形状。遇到不匹配时沿用原生采样器。可用 `&r18StartupSsr=native` 作同构建对照。

## 证据

1440×1000，Edge 无头，真实 NVIDIA WebGPU。同批 GPU API 记录显示，4096×2048 的 R18 镜面 HDR 写入由三次降至一次，减少 134,217,728 字节上传。Three 的纹理分配统计也恰好减少 128 MiB。1×1 黑纹理与常量零色均去掉了两份 HDR，最终使用无需纹理采样的常量。

独立配对中，参考与常量方案的完整首帧 GPU 结算分别为 26.87、26.24 秒。未命中标记在两张真实 SSR 附件中各约 13.7 万像素，均为零色。两张附件各有约 3.5 万有效命中，无非有限值。全景与开门截图的车身区 8 位平均绝对差分别为 0.219 与 0.282，地面倒影区为 0.111 与 0.131。

第二轮交叉测量的绕行 SSR GPU 通道中位数从 0.328 ms 降到 0.262 ms，分离时两组均为 0.328 ms。交叉测量的参考完整首帧为 25.61、26.00 秒，常量方案为 26.19、26.32 秒。首帧用时目前没有稳定的改善证据。采用依据是移除重复上传、减少实际纹理分配和绕行通道耗时。

可复现报告及截图位于 `artifacts/r18-startup-deep/`。API 跟踪会影响用时，实际加载与交互对照独立执行。场景提交、GPU 队列结算和显示器实际呈现分别记账。

生产构建、1009 项前端单测、工具测试、三件展品联合回归及 R18 管理取景与真实设备恢复均通过。联合回归的首帧 GPU 结算为 28.47 秒。全库 `npm run check` 在已有 `PERFORMANCE_OPTIMIZATION.md` 的格式检查处停止，其余步骤已单独完成。

5181 实机更新后，完整首帧 GPU 结算的一次冷启动为 31.43 秒，两张 SSR 附件的命中、零色未命中和原距离标记通过检查。30 秒稳定性仍有改善空间。
