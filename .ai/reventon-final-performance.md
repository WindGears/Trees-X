# Reventón R18 加载与实时性能对照

后续首帧追踪定位并消除了 SSR 的冗余 HDR 上传，最新证据见 [R18 首帧与反射开销实测](reventon-startup-profile.md)。

## 正式组合

R18 答辩入口复用同一逻辑帧的反射空间过滤、时域过滤与主软箱阴影过滤结果。摄影棚 Bloom、SMAA 和材质采样共用这些结果。预编译和场景切换继续由原有租约和资源所有者管理。

最后一次实际变化后，至少绘制 32 帧并等待 850 ms。DDGI 或阴影仍在准备时继续更新。相机、部件、灯光、取景尺寸和可见性变化会唤醒原 Tres 调度。DDGI 继续使用既有 15 Hz 上限和完整射线预算。

有至少 12 个逻辑处理器的已校验汽车 WebGPU 答辩入口使用 6 路解码。支持 BC 且优先采用 BC7 的设备使用本机预转码缓存。74 张纹理由项目内同一 Basis 转码器生成，保留尺寸、颜色空间、透明和完整 mip。逐级 Zstd 解压后的 BC7 块逐字节核对。缓存共 405,295,089 字节。缓存缺失或校验失败时读取原 KTX2。3 路下载、驻留上限和取消规则继续适用。[KTX2 格式规范](https://registry.khronos.org/KTX/specs/2.0/ktxspec.v2.html)

输出尺寸、R18 布光、车漆和玻璃、4K 资源、双射线 SSR、软箱自阴影、DDGI、地面倒影和抗锯齿均按原 R18 参数绘制。

## 对照与取舍

Edge 无头进程通过真实本机 API 加载同一 R18 资源，实际绘制 1440×1000。原始报告分别保留场景提交间隔、采样的 GPU 队列等待及按通道的 GPU 时间。初轮大量画质档位对照时外部 GPU 负载波动，后续在低负载下配对复测。队列结算与场景提交均不能当作显示器呈现时间。

## 最终构建测量

在同一生产构建切换 `r18Perf=reference` 比较。参考首轮界面 23.32 秒可操作，首帧 GPU 队列于 34.09 秒结算。优化组三次冷启动分别为 18.41／27.11、18.62／28.02、19.09／27.66 秒。每次首帧均确认实际 WebGPU、R18、主软箱阴影及 DDGI 已接入。

| 操作，各 30 秒 | 场景提交次数/秒，参考 → 优化 | JS 提交间隔 P95，参考 → 优化 | GPU 队列等待中位，参考 → 优化 |
| -------------- | ---------------------------- | ---------------------------- | ----------------------------- |
| 绕行           | 47.2 → 57.4                  | 27.1 → 22.0 ms               | 41.3 → 35.0 ms                |
| 开门           | 38.4 → 45.9                  | 32.1 → 26.9 ms               | 51.2 → 41.7 ms                |
| 分离           | 38.3 → 43.5                  | 32.1 → 29.6 ms               | 52.1 → 44.9 ms                |

5.5 秒静止窗口中，完整绘制提交由 249 次降到 0 次。两组各 80 个已初始化模型纹理，原生格式为线性和 sRGB BC7，按实际尺寸、mip 与块格式估算的逻辑存储均为 1,789,571,840 字节。同取景 8 位图的车身与地面倒影区域平均绝对差为 0.25 和 0.118，重复参考组为 0.206 和 0.112。显示器呈现预算仍待验证。

## 各项试验

| 比较项                      | 实测与决定                                                                                                                                                                                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 同帧复用                    | GPU 查询中反射空间与时域各由 3 次/帧减到 1 次/帧，软箱阴影过滤由 2 次/帧减到 1 次/帧。静图对照中的车身差异接近重复基线的随机采样差异。采用。                                                                                                                           |
| 静止调度                    | 配对测试中 5.5 秒静止从 276 个画面降到 0 个。操作恢复真实渲染。采用。                                                                                                                                                                                                  |
| 1、2、3 帧 GPU 排队上限     | 两帧上限在最终候选的分离段把队列等待中位从 42.9 降到 27.9 ms，提交率从 47.6 降到 37.5 次/秒。保留原提交方式。                                                                                                                                                          |
| 共用历史深度、法线          | 减少约 15.1 MiB Three 纹理记账。短测绕行与分离收益方向不同。留存实验。                                                                                                                                                                                                 |
| 2、4、6 路解码，3、6 路下载 | 低负载短测 6 路解码加原纹理的解析阶段约 3.73 秒，参考 4 路约 5.36 秒。6 路下载收益不足以改变下载预算。                                                                                                                                                                 |
| 原 KTX2、裸 BC7、BC7＋Zstd  | 裸 BC7 约 1.66 GB。BC7＋Zstd 在低负载配对中将解析阶段从约 5.36 秒缩到约 3.74 秒。采用带校验的本机压缩缓存。                                                                                                                                                            |
| 提前上传、首绘时上传        | 延迟上传的首帧 GPU 结算比同批提前上传对照更晚。沿用提前上传。                                                                                                                                                                                                          |
| HTTP gzip                   | GLB＋EXR 由 126.3 MB 变为 73.1 MB。该本机样本中两文件浏览器传输分别多用约 89 ms 和 13 ms，整体启动波动主要来自其他阶段。保留普通本机传输。                                                                                                                             |
| Chromium 持久配置           | 同一专用配置新建与两次重启的首帧 GPU 结算为 28.27、28.24、26.24 秒。沿用浏览器和驱动管理编译缓存。WebGPU 接口没有可移植的应用级已编译管线文件。 [Chromium GPU 缓存实现](https://chromium.googlesource.com/chromium/src/gpu/+/641ae9a286662b792b5e0653d35ee0c0d1483c83) |
| 反射降采样与过滤            | 比较单射线、0.75/0.5 分辨率、0.75/0.5 步进质量、关闭 SSR 和关闭过滤。低分辨率实验出现反射缺失，关闭过滤时出现颗粒。沿用完整双射线与过滤。                                                                                                                              |
| 间接光与阴影                | 比较 DDGI 8/12/15 Hz、屏幕 SSGI 两档、关闭间接光、关闭软箱自阴影及限制间接光接收区域。不同档位影响暗腔或动态更新，区域分支未取得稳定收益。沿用完整 DDGI 和自阴影。                                                                                                     |
| 地面与画面处理              | 比较 0.75/0.5 地面反射分辨率、2/0 样本 MSAA、关闭地面反射、SMAA、主画面 MSAA、Bloom。低负载下尚无证据表明削减地面预算有稳定收益。关闭主要效果会改变倒影、高光或细边。沿用原预算。                                                                                      |

深度金字塔、跨设备着色器二进制和超分没有纳入本轮实测。当前 Three r185 的 RenderBundle 会记录初始可见列表，摄影棚淡出、透明排序和部件构图变化需要另行验证后才适合替换原路径。

## 本机准备与复现

在已登记的 4K 运行包上执行 `npm run asset:reventon-native-textures` 生成本机缓存。生成器使用 Node 22.15+ 的 Zstd 接口。随后用 `TREES_DEMO_SHOWCASE=1` 运行既有 `demo:prepare` 与 `demo:start`。准备阶段核对衍生文件摘要及原包、Basis 文件身份。 [Node.js Zstd API](https://nodejs.org/download/release/v22.15.1/docs/api/zlib.html#zlibzstdcompresssyncbuffer-options)

R18 地址为 `/?renderPipeline=showcase&product=reventon`。添加 `&r18Perf=reference` 可在同一构建中比较原调度和转码路径。样本、截图、后台运行脚本和未晋级实验的源码归档位于 `artifacts/reventon-final-perf/`。本机派生贴图和原始采样报告由 Git 忽略。

## 联合回归

三件展品的同源浏览器回归和工作台切换通过。联合回归复用一个浏览器进程并拦截所有请求，汽车该次为 22.37 秒可操作、33.67 秒首帧 GPU 结算。独立冷启动的 30 秒结果有运行条件。汽车管理预览通过取景回填、姿态和真实 GPUDevice 丢失恢复检查。两份报告分别保存在 `showcase/report.json` 与 `admin/report.json`。

前端构建、类型与 ESLint 检查、1007 项前端单测、工具测试和本机资源核验通过。全库 `npm run check` 在工作区已有的 `PERFORMANCE_OPTIMIZATION.md` 格式检查处停止。后续检查已单独运行。

本机演示包重建后从停止状态启动，5181 入口为 18.65 秒可操作、27.37 秒首帧 GPU 结算。真实鼠标拖动唤醒静止场景并改变镜头，调整窗口至 1280×720 后保持单 Canvas。证据见 `release-r18.json`。
