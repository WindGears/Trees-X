# R18 材质程序复用

首次绘制追踪显示，表面、主画面和地面倒影会为多组汽车零件生成相同结构的节点图。每个运行材质原来创建独立的环境引用节点，Three r185 将该身份纳入材质程序键。

R18 答辩路径按探针与投影方式复用环境节点。程序键继续区分主灯遮挡、局部面积光镜面和地面反射类别。普通 BC7 纹理按格式、颜色空间、UV 通道、采样参数以及各贴图槽共用同一张贴图的关系分组。其他纹理按实际对象区分。每个零件仍由 Three 的材质引用节点提供自己的颜色、材质数值与贴图。绑定随当前摄影棚释放。[Three r185 NodeManager](https://github.com/mrdoob/three.js/blob/r185/src/renderers/common/nodes/NodeManager.js) · [MaterialReferenceNode](https://github.com/mrdoob/three.js/blob/r185/src/nodes/accessors/MaterialReferenceNode.js)

在同一生产构建上使用 `&r18Projection=reference` 对照。全部运行使用 1440×1000、原生 BC7、DDGI、软箱自阴影及同一份现有管线缓存。

首帧统计中的程序数为 221，uniform 缓冲区数量由 1138 降到 916。四组全景、开门、分离和亮橙换色截图中，新旧车身区域的 8 位 RGB 平均绝对差为 0.134–0.232。两次原路径之间为 0.104–0.205。地面取样区差异不超过 0.00013，灯板取样区一致。这里记录的是短时后台绘制和 GPU 队列完成时间，屏幕呈现由独立测试验收。

开门实绘中按物体、材质和通道核对 355 组 BC7 绑定，两路使用的贴图槽一致，均未观察到引用其他零件的 BC7 贴图。禁用原生管线缓存后，GPU 队列在 23.46 秒结算。三展品切换、管理预览、取景回填及真实 GPUDevice 丢失恢复通过。生产构建、1014 项单测、架构、模型及相关工具测试通过。全库 `npm run check` 停在已有的 `PERFORMANCE_OPTIMIZATION.md` 格式项，后续步骤单独运行。

面积光漫反射专用计算留在试验中。原型的旧缓存匹配下降，GPU 结算延长。先用生产版节点复用测量，后续单独比较重建缓存后的面积光实现。

原始结果与截图在 `artifacts/r18-startup-deep/graph-production-*`。节点图追踪、贴图绑定与管理端证据分别为同目录 `graph-share-paired-*`、`graph-binding-audit-*` 和 `graph-admin/report.json`。
