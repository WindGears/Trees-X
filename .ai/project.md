# 项目与阶段

## 当前范围

**2026-09-30 最新用户范围调整：本次 Reventón 只做技术验证，「差不多就行」，不再以匹配原参考图的极致材质光影作为交付门槛。** 保留当前已实现的 Three.js 实机、Blender 烘焙资产、开门→座舱→展开→合拢及播放控制，以真实动作和可用流程验收。停止额外外观校准；照片级匹配与性能优化留待用户另行要求，不作为本阶段未完成项。`browserQualityApproved:false` 仍如实保留，不表示技术验证失败。此调整优先于下方旧画质门槛。

**2026-09-30：Reventón 已进入项目实机。** `/?product=reventon` 使用 Three.js 绘制完整 GLB、烘焙 PBR/AO、实时 HDR 反射和随姿态变化的接触阴影。约 16 秒的开门→座舱→部件展开→合拢流程由 GSAP 驱动真实对象，可播放、暂停、定位章节和进度，不提供自由旋转。目录现有九件，原七件与打字机保留。模型身份、失败重试、上下文恢复、切换/释放和桌面/移动基础导航已有自动化证据；源 beauty 参考图的整体画质等效尚未验收。以 [实机约束](reventon-realtime.md) 与 [实机验收](reventon-runtime-validation.md) 为当前状态，下方 9 月 25 日影片方向仅作已撤销的历史记录。

**2026-09-28 方向纠正：用户要的是烘焙阴影/材质后的真实三维实机 Demo，不是影片。** 以 [Reventón 实机约束](reventon-realtime.md) 为准；以下旧记录中的视频交付方向已撤销。原几何、贴图、动作继续复用，前台取消影片展品入口，后续交付必须由 Three 实时绘制并执行开门、座舱、分解与复原。

2026-09-25 当前工作转入 Reventón 的 Blender 本地离线演示。已完成原几何/内嵌贴图恢复，以及独立的开门、座舱、部件分离动作验证工程和三张 4K 关键帧；完整影片尚未渲染。用户明确选择「先达到原参考图的材质光影，再渲染完整动画」。当前继续静帧校准，直接恢复 VPB 几何、逐件材质绑定及 UV 的候选工程与旧 Rhino 动作工程分开保存。该演示最终不提供自由操纵。当前七商品 Vue 前台尚未改变，不将预期播放器写作已实现。具体状态见 [Reventón 前置结论](reventon-preflight.md) 与 [静帧验收](reventon-validation.md)。

2026-09-21 已按确认方案改造为桌面沉浸式展厅：默认欣赏商品，右侧操作面板按需展开，顶部一键打开完整控制台。此要求明确替代旧版「完整控制台必须首屏常驻」。三件主展品为桌面音箱、迷你赛车、陶盆绿植，其余四件保持目录及资产支持的交互。桌面电影画质仍为 DPR 上限 2、Composer 1.0、8× MSAA，不因帧时间自动降低画质；音箱按摄影棚方向不显示粒子，其他商品保留 1600 粒子。移动端仅做 390px / 320px 基础兼容。

Phase 1 与单商品完整探索已完成。Phase 4 桌面视觉增强现已实现：符合能力门槛的桌面启用 HDR 金属反射、能量环、确定性粒子、模型扫描覆盖层、Bloom、暗角与一次 2.4 秒演出；音箱以以下专属摄影棚方案替代环、粒子与扫描。移动端、减弱动态与能力不足设备继续使用基础场景。鼠标、键盘、触控和手势共用同一套聚焦与相机状态，任何用户输入都能中止视觉演出。

2026-09-23 已实现桌面音箱主动演绎样板：面光、细纹金属和旋钮几何增强可见外观；默认仅揭示灯光，无自动运镜。用户主动播放 7.8 秒旋钮特写 → 完整轮廓 → 外观分层 → 合拢短片，可随时接手；减弱动态直接到完整外观。该扩展复用现有 Canvas、相机、控制台和输入桥，不表示真实内部构造。工程与浏览器验证记录、视觉复核状态见 [音箱样板验收](speaker-film-validation.md)，所有权见 [音箱主动演绎架构](architecture.md#音箱主动演绎)。赛车和绿植的专属短片仍未实施，先完成当前音箱样板验收再扩展。

2026-09-19 已复用 heritage-museum 商品改造版的六个 GLB/封面，并接入本项目目录、分类、搜索、URL 直达与单 Canvas 商品切换；连同 FORM / 01 共七件。结构展开只移动现有节点，按资产能力启用，不推断真实内部构造。手柄与边桌为单体模型。多人/多物体同时陈列的三维空间、滚动叙事、AI 讲解和后台仍未进入实现。整合记录见 `heritage-integration.md`。

2026-09-14 真人验收未通过：用户确认手能识别，但指针抖动、捏合时目标丢失。现有自动化通过不能作为交互可用性验收。社区调研与下一轮调整依据见 `gesture-research.md`；先解决指针稳定与目标捕获，再扩展功能。

随后已实现稳定性修订：One Euro 指针/掌心滤波、64/96px 吸附边界、先瞄准再捕获目标、指尖移动容忍、掌心明显移开取消、250ms 丢失宽限、两步校准和可见状态/诊断。手势确认现在进入与键盘按钮相同的部件聚焦镜头；实现与自动化完成，新版本的真人验收仍待用户实测。

## 路线与验收

| 阶段 | 交付内容                           | 验收条件                                                                     |
| ---- | ---------------------------------- | ---------------------------------------------------------------------------- |
| 1    | 框架、规范、基础场景               | 干净安装与构建成功；GLB 实际加载；旋转缩放复位可用；失败可重试；卸载释放资源 |
| 2    | GSAP 入场、相机路径、ScrollTrigger | 镜头与手动控制不会争夺；离开页面清理；减弱动态有静态替代                     |
| 3    | 部件拾取、信息、材质、爆炸视图     | 稳定部件 ID；键盘替代入口；复位一致；共享材质不会串色                        |
| 4    | HDR、Bloom、粒子、Shader           | 已实现；保留能力门控，固定桌面画质，按运行环境记录帧时间                     |
| 5    | 商品管理、上传、分类、浏览记录     | 先确定后端与持久化方案；鉴权、文件校验、删除与权限边界经过验证               |

## 开发顺序

说明职责和数据流 → 小批量实现 → 类型与生命周期验证 → 桌面/移动端检查 → 更新文档。后续阶段应独立迭代，不以假按钮表现尚未实现功能。

## 未决事项

当前以原创概念模型与用户参考项目的六个 CC0 资产作为展示样品。正式品牌、部署平台、账号体系与数据库仍待确认。参考项目的 Spring Boot 后台可供下一阶段适配，但尚未迁入本项目。当前 HDR 为 Poly Haven CC0 环境资源。

本轮实现与逐项验证见 `exhibition-validation.md`；设计真值为根目录 `DESIGN.md`。后台、AI 讲解、多人空间和截图分享仍属于后续范围。
