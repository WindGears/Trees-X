## 设计专属性判定

**已经是一套为三维物件观察设计的展厅，专属性中上；尚未达到完成度很高的商品艺术指导。**

第一眼的主角确实是模型。中文品名、短句、自由旋转和按需侧栏共同构成清晰的展示语法，没有恢复后台式常驻控制台。音箱的银灰反射、赛车的暖色展台、绿植的无环绿色空间，能读出三种不同的物件性格。尤其绿植的自然轮廓与留白，比单纯更换科技背景色更接近产品自身。

界面结构可以被其他三维物件复用，这在多商品系统中是合理一致性，并非缺点。尚未足够专属的部分在交互层：三件物品的首个热点都用同样的大圆与标签压在最值得观察的位置；音箱导览把普通部件说明和导览讲述同时堆入侧栏；完成导览后又退回通用的“开始导览”。产品细节已经被选出来，却还没有被组织成足够精确的观察节奏。

当前最值得提升的不是加特效，而是让探索动作、当前讲述和模型特写保持同一焦点。已有深色、金属和克制科技光方向应保留，不需要重做成另一种风格。

## 认知负担

默认欣赏状态负担低；激活导览、打开完整控制台或进入目录后升至中等。下列检查是按当前流程最差的相关状态计，共 3 项未通过，并不意味着每个首屏都很复杂。

| 检查项 | 结果 | 证据 |
|---|---|---|
| 单一焦点 | 通过 | 主模型仍显著大于界面，正常欣赏可不打开任何侧栏。 |
| 分块 ≤4 | 通过 | 四探索入口、三配色、三部件、三视角都有明确分块。完整控制台虽长，仍按功能分节。 |
| 相关项分组 | 通过 | 视角与缩放分开，侧栏标题与区域清晰。 |

| 一次一个决策 | 未通过于导览 | 正在跟随故事时，仍并列呈现部件选择、部件全文、返回全景和导览全文；自由探索与引导探索争夺位置。 |

不要把所有可见按钮简单相加当成一个决策：底部三视角与三缩放/复位动作有分隔，四入口也单独分组，不能据此宣称首屏有十几项选择。目录可用“精选三件 / 继续浏览”两个清晰组降低初次选择负担；完整控制台的高密度属于用户主动选择，优先级低于主导览。

## 情绪旅程

1. **进入：安静、可信。** 留白与真实模型让用户先停下来；绿植尤为自然，音箱反射能让人理解旋转的意义。
2. **尝试：具有掌控感。** 明确的拖动/滚轮提示、自由视角和按需侧栏让第一次点击成本低。
3. **深入的低谷：开始导览后，需要重新寻找讲述。** 音箱镜头成功靠近，但侧栏新插入的部件说明把当前步骤挤走；视觉动作与讲解脱节。
4. **体验高点：物件形态真的发生变化。** 音箱分层、绿植叶片特写是真正围绕资产的体验，胜过继续增加装饰。
5. **结束偏弱：完成导览后直接回到开始卡。** 模型保留分层状态符合需求，但缺少“已看完”的确认与自然去向；用户的结束记忆是一个恢复原样的功能区。
6. **摄像头入口的安抚合理。** 开启前就说明只在本机处理、可被鼠标接管，并允许跳过示范；实际识别和疲劳感未经本次真人测试。

## 做得好的三点

1. **“先欣赏，再探索”已落到结构。** 默认没有信息墙，打开细节后侧栏与场景分开，画面仍保留一个清晰模型。在 1280×720 也没有退回常驻工具后台。
2. **三件主展品有真实的舞台差异。** 音箱冷金属、赛车暖色底座、绿植自然背景与去圆环处理，可直接从当前页面识别，不只存在于文档里。
3. **探索具有可靠的退路与诚实文案。** 返回全景、退出导览、关闭侧栏、目录空状态恢复都有；不编造价格和性能，结构演示说明也明确限制。目录封面与当前真实模型一致。

## 优先问题

### 1. [P1] 开始导览后，当前步骤与继续按钮被新插入内容挤出视口

- **复现**：1280×720，打开 `?product=form-01` → 探索细节 → 开始导览。右侧上方新增“低音单元”说明和“返回全景”；“跟着看一看”的步骤文字落到面板底边之外，下一步完全在下方，需要滚动侧栏。
- **位置**：`StudioControls.vue:151` 的 `part-description` 在 `StudioControls.vue:162` 的 `ProductGuide` 之前；`ProductGuide.vue:36` 是实际当前步骤。
- **影响**：用户刚选择了引导，却被送回需要自行浏览的长侧栏；模型特写已变化，解释与下一步不在眼前。高配桌面也无法改善这个信息顺序问题。
- **改法**：导览运行时，把当前步骤作为侧栏主内容，部件说明并入当前步骤或折叠；让步骤控制条保持在面板可见底部。正常细节模式继续保留现有三个部件按钮与说明，不需修改三维资源或画质。
- **建议命令**：`$impeccable shape`、`$impeccable layout`。

### 2. [P1] 键盘操作打开侧栏与切换导览阶段时缺少连续的焦点落点

- **复现 A**：桌面点击或键盘激活顶部“完整控制台”，然后按 Tab，焦点去“作品信息”，未进入刚打开的控制台；随后还会经过场景与左侧控件。
- **复现 B**：音箱点击“开始导览”后，AX 报告焦点回到页面根；从第二步进入第三步时，“下一步”被“完成导览”替换，焦点再次回到页面根。完成导览后同样发生。
- **位置**：`StudioControls.vue:26` 仅记录 opener，打开时没有焦点交接；`ProductGuide.vue:22` 与 `:51` 条件替换正在操作的按钮。
- **影响**：键盘用户看得见新区域，却必须重新找回操作位置；读屏用户在连续故事中失去当前位置。这比单纯缺少快捷键更影响日常使用。
- **改法**：由键盘触发打开侧栏时将焦点放到侧栏标题或首个操作，并保留现有 Esc 与 opener 恢复；导览阶段替换后让焦点留在稳定的步骤区域/继续按钮上。使用非模态侧栏，不必新增会阻断场景的焦点陷阱。
- **建议命令**：`$impeccable harden`。

### 3. [P2] 常驻热点正好盖住用户被邀请观察的形态

- **复现**：音箱 1280×720 首屏的圆形热点盖在低音振膜中心，赛车首屏盖在车身上；1440×1000 绿植点击“叶片”后，亮色选中圆覆盖中心叶片。标签也持续贴在模型表面附近。
- **位置**：`src/assets/styles/gesture.css:102` 的 48×48 热点；`src/assets/styles/experience.css:195` 的常驻标签与 `:209` 的选中填充。
- **影响**：首次欣赏已经带着交互标记；特写后标记更醒目，反而遮住希望用户细看的材质与形状。弱化了高端商品展示的从容感。
- **改法**：保留键盘/触控的至少 48px 命中区域和手势模式中的清晰目标；普通欣赏态的可见标记可小一些，标签在悬停、焦点或细节模式展开。选中后的标记移到目标旁，通过短引线关联，不把高亮圆心压在被讲述细节上。不要直接删掉所有交互提示。
- **建议命令**：`$impeccable polish`、`$impeccable quieter`。

### 4. [P2] 目录的精选顺序与“下一件”路径不一致

- **复现**：目录第一排是音箱 → 赛车 → 绿植；选择音箱，关闭目录后点“下一件商品”，实际进入复古游戏手柄。赛车显示 07/07，绿植显示 05/07。
- **位置**：`ProductCollection.vue:21` 按 `featuredRank` 排序；`ProductSwitcher.vue:7`、`:9` 直接读取原始 `collection`。
- **影响**：目录明确承诺先看三件精选，但最直接的连续浏览动作绕过这条策展顺序；答辩或访客逐件浏览时会不必要地遇到次要展品。
- **改法**：用单一展示顺序配置供目录、前后切换和位置编号共用。稳定资产 ID 和原始来源信息不必变化。
- **建议命令**：`$impeccable clarify`，并做小范围导航逻辑修订。

### 5. [P2] 完成导览没有完成态，结束感与下一步都偏弱

- **复现**：音箱第三步 → 完成导览。右栏立刻重新出现“从轮廓走到细节……”与“开始导览”，模型仍处在分层状态；“完成导览”和“退出导览”均只把 `guideStep` 设为 null。
- **位置**：`ProductGuide.vue:57`、`:58`。
- **影响**：用户不能从面板判断自己是完成了故事还是刚关闭了故事；一次有高点的体验以恢复初始按钮结束。分层状态保留是正确行为，问题在于未解释这个结果。
- **改法**：保留当前观察状态，显示简短完成卡，例如“3 个角度，已经看完”，再给“返回全景”和“继续看下一件”两个清晰去向；重播保留为次要操作。不要自动复位用户的模型。
- **建议命令**：`$impeccable delight`、`$impeccable clarify`。

## 用户角色失败点

- **Jordan，第一次使用三维展示的访客**：能理解首屏品名、拖动提示和四入口；进入音箱导览时却只看到多出一段普通部件说明，不知道下一步被推到哪里。完成后再次出现“开始导览”，也缺少明确完成确认。
- **Sam，键盘或读屏用户**：目录对话框能进入关闭按钮，选定商品后标题也能接到焦点；但顶部打开完整控制台后焦点仍留在页头，导览更换按钮时回到页面根，连续探索被打断。问题是焦点路径，而非缺少可聚焦的按钮。
- **Alex，急于演示的熟练用户**：备用完整控制台提供所有功能，符合其需要；但照目录第一排记下的三件主展品，不能用“下一件”顺序演示。其要么记住原始编号，要么反复打开目录。

## 次要观察

- `ViewerControls.vue:35` 的立体、正面、背面没有 aria-pressed 或可见当前态。相机改变是反馈，但按钮没有帮助用户辨认已经在哪个视角；可在预设生效时选中、自由拖动后清除。
- 1280 音箱与赛车介绍有末尾单字换行；这是固定 248px 身份区与短句长度的局部排版问题，可用中文行尾平衡处理，不需要扩大整个文字栏。
- 首次手势说明的“跳过动作示范”在视觉上比下方“开启手势体验”更醒目，说明字体也较普通面板小；可在下一次手势真人验收时顺带调整操作层级。此次没有批准或启动摄像头。
- 390px 下页面正常改为纵向排列，四入口可用，面板不覆盖模型；但打开面板后无法同时完整看见模型和说明，是兼容布局的取舍，不应为此推翻桌面优先方案。
- 真实故障恢复、真人手势稳定性、完整辅助技术验证均未由本次设计浏览证明，不能据此宣布这些验收已完成。

## 可供主报告提出的问题

1. 能否把三步导览视为一段有开头、高潮和完成落点的作品讲述，而不是普通部件列表下面的附加功能？
2. 如果首屏只允许留下一个可见模型热点，它应帮助用户发现什么，而不是遮住什么？
3. “下一件”是否应当就是策展的下一件，让三件主展品形成一次连续、无需目录往返的体验？
